1. 对标拆解：DBX 的 MCP 到底是怎么搭的

维度DBX 实际做法（已核对原文）对 daro 的含义
进程形态独立 Rust 二进制 dbx-mcp，外面套一层极薄 Node 启动器发成 @dbx-app/mcp-server（平台二进制走 optionalDependencies）。客户端用 stdio 拉起（npx -y @dbx-app/mcp-server）。Node 只为兼容 npm/npx 配置，不含任何数据库逻辑MCP server 不是 app 的一部分。app 与 server 的关系是「共享存储 + 共享策略」，不是 IPC
连接来源直接读 DBX 连接存储 %APPDATA%\com.dbx.app\dbx.db，在 Rust 进程内自己建连执行；文档明写「DBX does not need to remain open」所以 dbx_open_table / dbx_execute_and_show 是仅有的两个要求桌面端在跑的工具，其余 16 个不需要
策略归属策略由 app 的「设置 → MCP」写盘，server 每次请求重新读取。旧环境变量 DBX_MCP_ALLOW_WRITES 被明确禁止放宽中央策略这是它最值钱的设计：改权限不必重启 MCP 客户端。daro 必须照抄这条语义
执行模式三档：只读 / 数据读写 / 完全访问，配一张「能力 × 模式」矩阵（即截图那张）。WHERE TRUE、1=1、_id {$exists:true} 仍按高风险处理矩阵照抄；「无法可靠分类的请求需要完全访问」这句文案也值得抄
范围收窄连接 allowlist（全部/指定）→ 数据库范围（全部/指定/禁止）→ 连接默认执行权限 → 单库覆盖；生效顺序由小到大回退：单库 → 连接 → 全局。越界返回 DATABASE_OUT_OF_SCOPE。连接只读、生产库保护、DB 账号权限是任何模式都压不住的硬上限Phase-1 只做「连接 allowlist + 连接级 mode + 全局默认」，单库覆盖列 Phase-2（§7 D5）
工具 allowlist可只暴露选定工具，服务端每次调用强校验，「即使客户端缓存了旧工具列表也会被拒」；开启连接作用域后，改连接的工具与 UI 工具直接隐藏隐藏 ≠ 授权。daro 侧必须同样在服务端判
传输stdio 默认；可选 Streamable HTTP：桌面端可直接托管，默认关闭，开后默认仅监听 127.0.0.1:5225/mcp + 本地生成 Bearer Token，进程内托管、异常自动拉起、轮换 Token 立即失效；绑非回环地址需同时满足 ALLOW_REMOTE=1 + --http-allow-remote + Host/Origin 白名单三个条件App 内嵌 HTTP 是 DBX 已经验证过的形态，不是我方独创的取巧路径（§4 的推荐依据）
结果规模max_rows 1–1000，默认 100，越界夹取而非报错；MongoDB/多语句脚本恒 ≤100与 daro 现有 sql_row_cap（服务端 LIMIT 下推）语义天然对齐
有状态会话dbx_open_session 固定一条后端连接（保留 USE/临时表/会话变量），空闲 30min 回收、最多 32 并发；显式事务只支持本地原生 MySQL，其余返回 TRANSACTION_UNSUPPORTED 而不是静默退化成自动提交原先判断「会话是 Phase-2 炫技」已撤回：P4 证明 daro 同样需要池，只是不需要把池暴露成工具（§3 P4、§7 D4）
批量执行dbx_execute_batch：方言感知拆句（字符串/注释/存储过程里的分号不破坏批次）、默认首错即停、continue_on_error、use_transaction（要求多语句、与 session 互斥、MySQL 含 DDL 直接拒绝因为隐式提交）daro 已有 lib/data/sql_split.dart 同能力，Phase-2 几乎白送
客户端接入页按客户端分 Tab 给可复制 JSON（Claude Code / Cursor / TRAE / VS Code / Windsurf / Codex / OpenCode / Cherry Studio）+「重新检查」状态探测；明写「DBX 只检测和提示 MCP 状态，安装与升级仍由 npm 完成」配置生成 + 状态检测是必须做的 UI，否则用户接不上
工具总数18 个（连接 5 / 结构 5 / 执行 3 / 会话事务 4 / MQ-Redis 3 中按构建裁剪 / UI 2）daro Phase-1 建议 10 个（§5.2）

2. daro 侧实测证据（决定形态的事实）

#事实取证方式结论
E1驱动层零 Flutter 依赖逐文件 grep -c package:flutter：drivers/{access,db_driver,mariadb,mysql,odbc_query,pgsql,sqlite,sqlserver}_driver.dart 全部 = 0；table_design.dart / sql_split.dart / db_data.dart = 0DBX「独立二进制复用 dbx-core」的前提在 daro 等价成立：MCP 能直接吃 DatabaseDriver，不必为 agent 重写数据访问
E2lib/data 只有 2 个文件碰 Flutterdb_types.dart:1-2（material + flutter_svg，类型图标/颜色）、sql_completions.dart:3（widgets，补全浮层）MCP 侧不 import 这两个即可，零重构
E3接口面已覆盖 DBX 大部分工具lib/data/drivers/db_driver.dart:120-262：listDatabases / listSchemas / listTables / listViews / listTableComments / listTableRowEstimates / listFunctions / listProcedures / describeTable / readTableDesign / getDefinition / previewTable / countTable / executeQuery / useDatabase / useSchema / serverSessionId / killSession18 个 DBX 工具里 daro Phase-1 要的 10 个全部有现成 backing 方法（§5.2 逐条映射）
E4「另开专用驱动实例」已有先例与教训lib/data/schema_sync.dart:1-14 头注释：比对/部署不复用 ConnectionManager 里连接树共享的长连接，因为反复 useDatabase 会改上下文、PG 家族还会断开重连，「既拖慢比对也会打乱树与查询页的运行上下文」直接复用 UI 活连接跑 agent 的 SQL 会互相污染会话。MCP 必须走专用驱动实例（§7 D4、P4）
E5connections.json 是全量覆写lib/data/connection_store.dart:59-69 save() 整文件 writeAsString；:31-45 load() 损坏时静默返回空若 sidecar 也写连接（add_connection），会与 app 内存态互相踩（后写者覆盖前者）。DBX 用 SQLite 有事务，我们没这保护 → Phase-1 不给 agent 写连接的权限
E6密码明文落盘lib/data/connection_store.dart:21-22 注释自认「当前以明文保存，后续可换加密存储」与 DBX 读 dbx.db 同级风险（本机单机）。硬约束：MCP 任何输出不得回显 password（§7 D7、P3）
E7纯 Dart exe 的打包隐患pubspec.yaml：sqlite3_flutter_libs: 0.5.42 锁定注释「0.6.0+ 是 EOL 占位包，不再捆绑 sqlite3.dll」→ 现在 SQLite 能跑是靠 Flutter 插件把 dll 拷进 build 目录（installer/windows/installer.iss:97 打包注释里也点名 sqlite3.dll）dart compile exe 出的独立 exe 不会自动带 sqlite3.dll，且 pubspec 含 flutter: sdk: flutter 时 dart pub get 走不通（需借 flutter pub get 产出的 package_config.json）。这是 stdio exe 的未验证构建链，须先做 spike（§4 排序依据）
E8本机工具链Dart SDK 3.13.0 stable / Flutter 3.47.0 stable满足 dart_mcp_server 的 SDK 门槛（见 D2）
E9没有「设置」页lib/widgets/top_menu.dart:261-293 菜单只有 文件/视图/… ；全仓唯一的设置形态是 theme_customize_dialog.dart + theme_store.dart（对话框级）「设置 → MCP」需要一个宿主：要么新建设置对话框/页，要么先挂「更多」菜单下单点（§6 W6）
E10Dart 官方 MCP 包现状dart_mcp_server（publisher tools.dart.dev，repo dart-lang/ai）1.1.2，页面自述「still experimental and is likely to evolve quickly」，只提 stdio，要求 Dart ≥ 3.9.0-163.0.dev官方包只覆盖 stdio，而 stdio 恰是 daro 的构建链风险项（E7）→ 用它并不能省掉最难的部分（§7 D2）

3. 已实测痛点（P1–P7，全部会改变设计）

本节是对自己上一版的纠偏：P1/P2 把超时与取消从「可选字段」升为前置条件（§5.1、§5.3）；P3 给 §4 的宿主顺序补了一条比构建链更硬的论据；P4 撤回「会话整体推到 Phase-2」的判断——池必须进 Phase-1；P5/P6 要求把「不支持」「改名脱钩」写成契约而不是异常文本；P7 是流程摩擦，不是技术风险。
#痛点取证（可直接跳转）对设计的强制影响
P1executeQuery 根本没有语句超时，且行数封顶不是无条件生效db_driver.dart:219-220 接口签名只有 sql / limit / offset，无 timeout 形参；全仓只有握手级超时（mysql_driver.dart:28 timeoutMs=10000、pgsql_driver.dart:43、sqlserver_driver.dart:35）。而 sql_row_cap.dart:19-30 的 _blockers（LIMIT/FETCH/INTO/FOR/LOCK/PROCEDURE/INSERT/UPDATE/DELETE）一命中就返回 null 不改写，注释原话「宁可退回旧行为也不能把用户的语句改坏」人用 UI 时旁边有「停止」按钮，agent 没有 → 一条语句能把 daro 挂几十秒且拿不到结果。① queryTimeoutSecs 是前置条件不是可选项；② 封顶被拒的语句必须在结果里回 rowCapApplied:false，让 agent 知道自己面对的是未封顶语句；③ 超时默认值不能一档通用（§7 D11）
P2超时了也未必取消得掉db_driver.dart:222-232：取消要第二条临时连接下发 KILL/pg_cancel_backend，且「需要服务端权限（MySQL CONNECTION_ADMIN、PG 同用户/管理员、SQL Server ALTER SERVER STATE）」；SQLite / Access 等本地文件型 serverSessionId() 返回 null，没有带外取消这条路超时后只能尽力而为：结果必须带 cancelAttempted + 失败原因；取消失败或无法取消时，该专用驱动实例直接销毁不回池（绝不能把一条仍在跑语句的连接放回池里被下一个请求复用）。这条直接写进 §5.3 错误契约
P3密码经常是不存的，stdio 形态下没人可弹connection_store.dart:21-22「密码仅当向导勾选『保存密码』时才会写入」→ ConnectionInfo.password 常态为空；db_driver.dart:270 connectionNeedsPassword() 是打开前是否需要密码的唯一入口；UI 侧靠 connection_password_window.dart:10（desktop_multi_window 独立子窗口）+ app_state.dart:463 setConnectionPassword() 补录内嵌形态能弹：agent 命中空密码连接时在 daro 里弹一次密码窗，人输完继续，一次授权长期可用；stdio exe 无交互面，只有「已保存密码」的连接可用（full 模式下让 agent 传密码 = 把明文密码写进 agent 的对话历史，不可接受）。→ 这是比 E7 构建链更硬的 D1 论据（§7 D1）
P4「另开专用驱动实例」= 每次调用重做握手，慢到不可用connection_manager.dart:99 _drivers 是 连接名 → 长连接（唯一的池，MCP 不能借）；每次新建实例 = 一次 TCP + TLS + 认证（握手超时都定在 10s，见 P1 取证）。agent 一轮对话连打 10 个工具就是 10 次握手撤回上一版把 session 整体推到 Phase-2 的判断。Phase-1 必须有 McpDriverPool：键 = 连接名|数据库|模式、空闲 TTL 回收、并发上限、上限外直接返回 POOL_EXHAUSTED 而不是排队到超时。DBX 的 30min/32 并发不是炫技，是被同一个问题逼出来的。暴露成工具的 open_session / 显式事务仍留 Phase-2
P5声明的数据库类型远多于有驱动的类型connection_defaults.dart 里 31 个 case（含 aliyun-rds-* / aliyun-polardb-* / aliyun-oceanbase-*）、db_types.dart 列 10 类，但 db_driver.dart:265 kSupportedDriverTypes 只有 6 个；createDriver()（:364-381）对 aliyun-rds-postgres 这类没有 case → 返回 null；走到 connection_manager.dart:134 是 throw UnsupportedError('暂不支持 ${conn.typeId} 类型的连接')MCP 侧必须先过 hasDriver()；不可用的连接在 daro_list_connections 里就带 supported:false 返回（别让 agent 调用时才发现），并把中文异常转成结构化 DRIVER_UNSUPPORTED —— 否则 agent 拿到一段人话错误会反复重试同一连接
P6一切按「连接名」索引，没有稳定 id → 改名同时孤儿化活驱动与策略db_data.dart:23-50 ConnectionInfo 字段全集（name/typeId/host/port/username/password/database/authMethod/group/isLive）无 id；connection_manager.dart:99 按名索引；ConnGroup（:113）同样「分组名即标识」（与 docs/connection-group-design-brief.html 同一病根）策略里的 connections[].name 与池键都会因改名脱钩，且脱钩方向是静默失效（旧名条目变成永久无效授权残留）。Phase-1 最低成本：ConnectionInfo.copyWith 改名路径上检测「该名字在策略/池里」→ 提示并同步迁移；根治要引入 id（§7 D10）
P7设置页需要的新组件必须进 submodule，一次改动两笔提交AGENTS.md 强制规则「禁止在 daro 中创建自定义 UI 组件」+ 组件速查表里没有「可复制配置代码块」；base-ui-flutter 是 git submodule（.gitmodules），新增组件按规则要走 src/<命名空间>/ + barrel export + CHANGELOG.md + example 演示页，再回主仓 bump 指针纯流程摩擦，但会真实拖慢 W7。可先降级用 base-ui 现成件规避（Input 只读 + Button「复制」），把 CodeBlock 组件推到确有第二个使用方时（§7 D12）

4. 推荐形态：core 纯 Dart，宿主先内嵌 HTTP、后加 stdio

lib/mcp/                      ← 纯 Dart 纪律：本目录禁止 import package:flutter（CI 用 grep 卡死）
  mcp_policy.dart             策略模型 + 判定（模式 / allowlist / 只读分类 / 夹取），每次调用重读盘
  mcp_errors.dart             错误码契约（§5.3）：结构化 code + 给 agent 的下一步建议，杜绝中文异常外泄
  mcp_pool.dart               McpDriverPool（P4）：键=连接名|库|模式，空闲 TTL 回收 + 并发上限 + 脏实例销毁
  mcp_protocol.dart           JSON-RPC 2.0 + MCP 握手（initialize / tools.list / tools.call / notifications）
  mcp_http_host.dart          Phase-1 宿主：HttpServer 监听 127.0.0.1:port /mcp + Bearer 校验
  mcp_tools.dart              10 个工具 → DatabaseDriver 调用 + 结果封装（列/行、truncated、超时/取消标记）
lib/widgets/mcp_settings_dialog.dart   设置 → MCP：模式矩阵 / 连接 allowlist / 工具 allowlist / HTTP 开关 / 客户端配置 Tab / 重新检查
bin/daro_mcp.dart             Phase-2：stdio 宿主（同一 core，仅换壳；受 P3 约束）
Phase-1 = App 内嵌 Streamable HTTP（§7 D1 推荐 A）
+ 密码可弹窗：P3 是本轮最强的论据 —— 空密码连接能在 daro 里弹一次窗让人补录，stdio exe 根本没有人可弹
+ 零构建链风险：不碰 dart compile exe 与 sqlite3.dll（E7）
+ 零双写风险：连接与策略都由 app 进程独占读写（E5）
+ 元数据缓存可复用，但执行仍走 McpDriverPool 的专用实例，不碰树上那条长连接（E4 + P4）
+ 白送 UI 桥：daro_open_table / 结果直接进当前标签页 —— 这是 DBX 要靠 Desktop bridge 才有的能力，我们天然可用，是唯一差异化卖点
− app 必须开着；只支持 stdio 的老客户端连不上
Phase-2 = 同一 core 加 stdio exe
先做 30 分钟 spike：flutter pub get 后 dart compile exe bin/daro_mcp.dart 能否跑通 + 手工放 sqlite3.dll 后 SQLite 连接是否可用。跑通才立项，跑不通就永久停在「内嵌 HTTP + 文档说明」。
落地后的价值是app 不必开着（对齐 DBX 主路径）；代价是 P3 直接生效 —— 只有已保存密码的连接可用，connectionNeedsPassword() 为真且密码为空的连接要在 daro_list_connections 里标 passwordMissing:true 并给 PASSWORD_REQUIRED，不接受 agent 传密码（会把明文密码写进对话历史）。

5. 实体字段与工具清单

5.1 新增实体 McpPolicy（落盘 mcp_policy.json，与 connections.json 同目录）

字段类型 / 默认说明
schemaVersionint / 1策略格式版本。DBX 有明确语义：「升级时未带策略版本的旧规则继续使用旧上限语义，不会放大权限」→ 抄这条，避免旧文件被新默认值悄悄放宽
enabledbool / false默认关闭（对齐 DBX「HTTP 服务默认关闭」）。用户不主动开，agent 一律连不上
http{host, port, token} / 127.0.0.1:5225, ''仅回环免鉴权可选；绑非回环必须同时有非空 token + 显式 allowRemote（照抄 DBX 的三条件门）。Token 一键轮换，旧值立即失效
defaultModeenum readonly | readWrite | full / readonly全局默认档，即截图那一列的三选一
connectionScope{all: bool, names: [String]}MCP 可见连接 allowlist。all=true 含以后新增的连接（DBX 原语义）
connections[]{name, mode?, databaseScope}连接级覆盖。mode 为空 = 继承全局。databaseScope = {all} | {include:[…]} | {deny}；越界返回 DATABASE_OUT_OF_SCOPE
注意：daro 的 ConnectionInfo 无 id、按 name 索引（与分组简报同一约定）→ 连接改名会让策略脱钩（P6），改名对话框需提示「该连接已授权给 MCP」（§7 D6 / D10）
tools[String] / 全选工具 allowlist。服务端每次调用强校验，UI 隐藏只是展示；不在名单内的连接变更类 / UI 类工具在收窄模式下自动隐藏（对齐 DBX）
maxRows / hardRowCap100 / 1000默认与上限，越界夹取不报错（DBX 原语义）。落到 executeQuery(limit:) 即由 sql_row_cap 下推服务端 LIMIT。P1：该下推不是无条件的（sql_row_cap.dart:19-30 的 _blockers 命中即不改写），故结果里必须回 rowCapApplied:false，让 agent 知道这条语句没封顶、别指望行数少就是全量
queryTimeoutSecs按模式分档：readonly 30 / readWrite 60 / full 300前置条件，不是可选项（P1）——executeQuery 接口本身没有 timeout 形参，MCP 侧必须自己包 Future.timeout。超时后走 serverSessionId() + killSession() 带外取消（db_driver.dart:222-232），但取消需要服务端权限、SQLite/Access 压根返回 null → 结果必须带 cancelAttempted 与原因，取消不掉就销毁该驱动实例（P2）
poolIdleTtlSecs / poolMaxDrivers600 / 8P4 逼出来的字段：MCP 专用驱动实例的缓存 TTL 与并发上限。超出上限直接返回 POOL_EXHAUSTED，不排队（排队会让 agent 等到超时还拿不到原因）。池键 = 连接名|数据库|模式，与 connection_manager.dart:99 的树上长连接完全隔离
passwordPromptaskInApp / denyP3：内嵌宿主默认 askInApp —— 命中 connectionNeedsPassword() 且密码为空的连接时，在 daro 里弹 showConnectionPasswordDialog 让人补录（复用现成独立子窗口），人取消才返回 PASSWORD_REQUIRED。stdio 宿主强制 deny，且任何宿主都不接受 agent 传密码
audit 建议 Phase-1 就带{enabled, path}每次工具调用一行 JSONL（连接/库/语句摘要/模式判定/行数/耗时/取消结果）。成本极低，但事后能回答「谁删了我的表」；P1/P2 的超时与取消是否真的生效，也只能靠它取证
派生不变量① 策略是上限而非授权：DB 账号本身的权限、驱动 isLive 与 kSupportedDriverTypes（db_driver.dart:265）永远压不过策略。② 任何模式都不得回显 password。③ 策略改动无需重启 MCP 客户端 —— server 侧每次调用重读盘（DBX 核心语义）。

5.3 错误码契约（P1 / P2 / P3 / P4 / P5 的落点）

为什么单列一节：本仓现在的失败路径是中文异常文本（connection_manager.dart:134 的 UnsupportedError('暂不支持 …')、sqlserver_driver.dart:61 的「连接超时(10 秒无响应)…」）。给人看很友好，给 agent 看是灾难——它读不出「该重试 / 该换连接 / 该问用户」，于是反复重试同一条死路。MCP 侧一律返回 {code, message, retryable, hint} 四元组，message 保留中文原文（对齐既有约定：中文提示保留原始堆栈）。
code触发条件retryable给 agent 的 hint（写进工具 description 与错误响应）
CONNECTION_NOT_VISIBLE连接不在 allowlist / connectionScope 内false「该连接未授权给 MCP，请让用户在 设置 → MCP 中添加」——不要换名重试
DRIVER_UNSUPPORTEDhasDriver() 为 false（P5：connection_defaults.dart 里 31 个 case / 去重 19 个 typeId，仅 6 个有驱动）false「daro 当前不支持该引擎的驱动，换 daro_list_connections 中 supported:true 的连接」
PASSWORD_REQUIREDP3：需要密码但未保存，且内嵌弹窗被用户取消 / stdio 宿主false「请让用户在 daro 里打开该连接一次并勾选保存密码」——绝不提示 agent 代传密码
DATABASE_OUT_OF_SCOPE库不在该连接的 databaseScope（抄 DBX 同名码）false先调 daro_list_databases 拿允许名单
MODE_DENIED语句分类出的最低模式 > 当前生效模式（§7 D6 白名单判定）false「当前为只读档，该语句需要 数据读写 / 完全访问」
WHERE_TOO_BROAD写档下 UPDATE/DELETE 无 WHERE 或 WHERE TRUE/1=1（抄 DBX 的高风险口径）false「补上可收窄的过滤条件，或让用户切到完全访问档」
TOOL_NOT_ALLOWED不在 tools 名单内（服务端每次强校验）false客户端缓存了旧工具列表，刷新 tools/list
QUERY_TIMEOUTP1：超过 queryTimeoutSecs视 cancelAttempted响应里必带 cancelAttempted / cancelReason；取消失败时 hint 写「服务端查询可能仍在执行，请勿立即重跑同一语句」
CANCEL_FAILEDP2：killSession 因权限或引擎（SQLite/Access 无会话）无法取消false「该驱动实例已销毁，重试会新建连接；本地文件库无法中途取消，请缩小查询范围」
POOL_EXHAUSTEDP4：并发专用实例数达 poolMaxDriverstrue带 retryAfterMs；服务端不排队，避免 agent 等到 QUERY_TIMEOUT 还拿不到真因
ROW_CAP_NOT_APPLIED warningP1：sql_row_cap 的 _blockers 命中，未下推 LIMIT—随正常结果一起返回，提示「行数少不代表是全量」
CONNECTION_FAILED握手/认证失败（沿用 mysql_driver.dart:83-91 已区分的 RST 与超时两类）true保留原始堆栈（对齐 release 0.5.1 的既有约定），hint 里区分「网络不可达」与「凭据错误」

8. 边界与验收

项Phase-1 验收标准
接通即用在 Claude Code 里粘设置页复制的配置 → 不重启 daro → daro_list_connections 返回 allowlist 内连接；改 allowlist 后不重启 MCP 客户端，下一次调用即生效（DBX 核心语义，必须实测）
默认安全全新安装 enabled=false，agent 连不上且得到明确拒绝原因；默认 defaultMode=readonly；未勾 allowlist 的连接在任何模式下都不可见
权限不可放宽单测钉死：任何工具输出不含 password；full 模式也不能访问 allowlist 外连接；不在 tools 名单内的工具即使客户端缓存了旧列表也在服务端被拒
不污染 UI E4 / P4agent 连续跑 USE other_db / 建临时表后，用户的连接树与查询页运行上下文不变（D4 的回归点）；且 connection_manager.dart:99 的 _drivers 里不会出现 MCP 专用实例
规模可控 P1max_rows 越界夹取到 1000 不报错；LIMIT 真的下推到服务端（复用 sql_row_cap，不是取回后再丢）；命中 _blockers 的语句必须带 ROW_CAP_NOT_APPLIED，不允许静默返回未封顶结果
超时与取消 P1 / P2对一条 SLEEP/pg_sleep 语句：到点返回 QUERY_TIMEOUT；MySQL/PG/SQL Server 上 cancelAttempted:true 且服务端会话确实终止；SQLite/Access 上明确返回 cancelAttempted:false + 原因，且该驱动实例被销毁不回池。验收要看审计日志，不能只看返回值
握手次数 P4同一 连接|库|模式 连续 10 次工具调用，服务端只发生 1 次握手（用连接侧会话计数或日志验证）；并发第 9 个请求返回 POOL_EXHAUSTED 而不是挂住
密码缺失路径 P3对未保存密码的连接调用工具 → daro 弹出密码子窗 → 人输入后本次调用直接成功（不必重试）；人取消或 120s 无人响应 → PASSWORD_REQUIRED；任何情况下响应体不含密码字段
不支持类型 P5对 oracle / mongodb / redis / snowflake 及 aliyun-* 连接：daro_list_connections 里 supported:false 可见，后续调用返回 DRIVER_UNSUPPORTED，不得出现 UnsupportedError 的中文堆栈外泄
改名守卫 P6改一个已授权连接的名字 → 弹提示且策略条目同步迁移；daro_list_connections 不出现幽灵连接，也不出现失效的孤儿授权
主题与交互设置对话框明暗双主题走 Tokens.of(context)；控件全部 base-ui（Button/Input/CheckBox/GroupBox），零 Material、零动画、点击走 Listener.onPointerDown
不做（写死边界）Redis / MongoDB / Kafka 工具（无驱动）、连接增删改、有状态会话与显式事务、批量脚本、自动写第三方客户端配置文件、远程非回环访问
