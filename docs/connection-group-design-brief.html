daro（Flutter 桌面数据库管理工具）· 分支 master@1d9f29c · Phase-1 MVP · 2026-09-20

已拍板（本轮问答确认）： 分组对象 = 连接 层级 = 单层 .ncx 承载 = 私有属性 Group="…"
目标：连接可按分组折叠管理；导出连接设置时把分组写进文件；导入时文件里出现本地不存在的分组 → 自动重建该分组，再把连接挂进去。

4. 需要你拍板的决策

编号决策选项我的推荐
D1私有属性 Group 写在 <Connection> 的哪个位置A 追加在末尾（Remarks 之后，不动既有相对顺序）/ B 插在 ConnectionName 之后（显眼）A。该文件的设计承诺是"属性顺序逐字对齐 Navicat 实测"，追加尾部是唯一不破坏既有顺序的做法；XML 属性无序，Navicat 读取不受影响
D2空分组能否存在A 能（独立 groups 列表落盘）/ B 不能（分组纯由连接派生，最后一条移走即消失）A。B 下"导入时分组不存在需重建"退化成给连接打标签，且无法预建分组、无法重命名空分组
D3分组折叠状态是否落盘A 不落盘（内存 _expanded）/ B 落盘A，Phase-1 少一个持久化字段与一条不变量；需要时 Phase-2 加

D5分组排序与未分组的位置A 按首次出现顺序、未分组排最后 / B 名称拼音排序 / C 未分组排最前A。与 Navicat「未分组连接沉底」观感一致，且无需新字段

5. 边界与验收

Phase-1 不做（显式推迟）

  • 多级嵌套分组、拖拽移动连接、分组手动排序、分组配色/图标
  • 把分组写回 Navicat 可见字段（Navicat 无此概念）
  • 对象面板 / 查询 / 备份的分组（本轮只动连接）

测试计划（flutter test）

  • navicat_export_test：属性顺序快照 + Group 尾部位置 + 空分组不写属性
  • navicat_import_test：含 Group 往返对拍；缺 Group 的老文件 → group == ''
  • connection_group_test（新）：重命名 / 删除分组回落 / 导入自动建组幂等（同组两次不产生重复条目）
  • database_tree_group_test（新）：分组头渲染顺序、未分组沉底、筛选后分组头随子项显隐
  • 全部改动跑 flutter analyze 零告警 + 现有 15 例连接/向导测试不红
实现风险点（会主动避开的坑）
  • 连接改名 / 复制 / 编辑走 _uniqueNamed 与 _migrateTabsConnection：分组变更不得触发标签迁移与驱动重连（只改分组 = 纯树视图变化）。
  • ConnectionStore.save 是全量覆写：批量导入必须一次落盘（现有 addConnections 已如此，建组也须并入同一次 _persist）。
  • 分组节点沿用现有零延迟约定：Listener.onPointerDown 展开/折叠，禁 InkWell、禁 onTap+onDoubleTap 同注册。
  • 导入 378 条这种量级：分组集合用 Set 去重后再建，不得逐条 notifyListeners。
